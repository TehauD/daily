# The Daily: Schema First, Pipeline Second

Copying an existing pipeline made the first step faster. It did not make the new source compatible.

## The theme: Generated tables are not a substitute for design

I worked through a transcribed SharePoint-to-Synapse pipeline session using Azure Data Factory. We copied an existing pattern, configured the new SharePoint source, previewed the list, and pointed the sink toward Synapse.

The load then exposed the real work: schema mapping, indexed columns, problematic inferred types, auto-create failures, and data-quality questions. The source was large enough that performance and timeout behavior also needed measurement.

The session produced a practical fallback. Export a bounded subset to CSV, create the initial table deliberately, then return to pipeline testing with a known schema.

## Field notes from the build

The SharePoint connector exposed many platform fields that were not required downstream. Selecting only required fields reduced ambiguity and helped isolate type problems.

Automatic table creation failed with a columnstore-related error. The team also identified indexed source columns as a possible blocker. The evidence supports active troubleshooting, not a resolved production load.

I accepted several concrete tasks: test handling of negative balances and duplicate or inconsistent account identifiers, investigate indexed-column behavior, create a subset export for manual table creation, and benchmark the full load.

The data-quality questions mattered as much as the connector. Multiple records could represent different people while sharing or varying identifiers in ways that could create false duplicates. The task was to verify behavior, not silently deduplicate.

I also began importing packages into a controlled Azure Artifacts feed and described a formal intake and promotion path with third-party security scanning. This advanced the package-management pattern, but the later review had not yet occurred, so I did not treat it as an approved enterprise solution.

A separate group lifecycle notification showed that a migration workspace had expired and been deleted with a restoration window. I did not count that automated message as completed work. It reinforced the need for ownership and lifecycle automation around temporary collaboration assets. #type/win

## What moved

-Configured and tested a SharePoint-to-Synapse pipeline path in Azure Data Factory.

-Identified schema mapping, indexed columns, inferred types, and columnstore creation as blockers.

-Defined a CSV subset fallback for deliberate table creation.

-Accepted validation of duplicates, inconsistent identifiers, negative balances, and load performance.

-Began importing Python packages into a controlled Azure Artifacts feed with a formal promotion concept.

## The reusable pattern

Profile before loading. Generate a source schema report, classify identifiers separately from measures, select required columns, define the target table explicitly, and validate edge cases before scaling volume.

## Standing takeaways

-Reusing a pipeline does not remove source-specific assumptions.

-Automatic schema creation is a convenience, not a contract.

-Suspected duplicates require business validation before removal.

## Open thread

The pipeline still needed a stable target schema, successful benchmark, and verified treatment of indexed fields and financial edge cases.
