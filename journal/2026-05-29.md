# The Daily: Standards Should Execute

A standard that depends entirely on a reviewer remembering every rule will eventually become inconsistent. Today I started reframing reporting standards as something software could evaluate.

## The theme: Move quality checks left

I accepted a new automation concept for Power BI quality review. The idea was to inspect a report or semantic model against an agreed standards list and return interactive guidance to the developer. The goal was not to replace judgment. It was to remove repetitive checks and make the expected corrections visible earlier. #type/idea

The work was still in discovery. Standards for semantic models and data loading were being assembled, and the automation needed its own tracked work item connected to the broader continuous-improvement effort. I did not call the checker implemented.

## Field notes from the build

The concept aligned closely with another metadata-enrichment effort. Both systems needed controlled rules, evidence from the artifact, and a response that distinguishes confirmed findings from recommendations. Starting with a clean contract was more important than reusing code prematurely.

The AI intake process also received another round of feedback. An early requestor completed the business portion but could not confidently answer the platform configuration questions. That validated the proposed split between requestor intent and governance execution. The request also needed executive sponsorship before review. #type/win

A deployment pipeline for a separate web application advanced to a new failure. The service principal appeared to need additional access at the resource-group layer, and the application owner escalated the permission question. The evidence supports that the blocker was identified and routed. It does not support that deployment completed. #type/win

I also explored how structured source formats might affect the legal agent. A colleague suggested comparing PDF, Markdown, and JSON representations with a small, domain-authored question set. That was a strong evaluation idea because it converted a format preference into a controlled experiment. It remained explored, not validated. #type/experiment

Preparation for the first machine learning community session continued, and discovery around a clinical risk model raised basic questions about how the score had been designed. I treated those questions as a reminder to understand lineage, intended use, and intervention timing before attempting to extend a predictive model.

## What moved

-Defined a concept for automated Power BI standards checking and developer guidance.

-Separated the checker into its own tracked enhancement connected to broader standards work.

-Validated that governance-owned fields should be removed from the requestor-facing intake.

-Identified and routed a service-principal permission blocker in an Azure DevOps deployment.

-Explored a controlled comparison of PDF, Markdown, and JSON grounding formats.

-Advanced preparation for a machine learning community session.

## The reusable pattern

Express standards as machine-readable rules with identifiers, severity, evidence requirements, remediation guidance, and exceptions. Run the rules before peer review and return findings in a stable schema.

The future state is continuous quality enforcement. Commits trigger artifact inspection, deterministic checks run first, AI explains complex findings second, and reviewers focus on judgment rather than mechanical compliance.

## Standing takeaways

-Standards create more value when they can be tested automatically.

-Suggestions about model inputs should become experiments, not opinions.

-A new deployment error is progress only when it narrows the blocker.

## Open thread

The standards checker still needed an authoritative rule set, artifact access method, and evaluation plan.
