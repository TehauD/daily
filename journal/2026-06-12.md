# The Daily: Protect Before You Publish

I loaded a large dataset, then realized the permissions should have been designed first. The correct response was not to defend the work. It was to remove the exposure and rebuild safely.

## The theme: Access belongs in the ingestion plan

A SharePoint list migration completed, but breaking inherited permissions failed because of the list size. The development site included broader access than the sensitive data justified. #type/win

I considered hiding columns, but that was not a sufficient control. I chose to purge the list and reload it after access was constrained. The extra work was the right tradeoff. #type/decision

## Field notes from the build

This was a clean example of sequencing failure. I had focused on schema and load mechanics before proving the access boundary. Once records existed, the list was too large for the intended permission change to complete reliably.

The reusable correction is straightforward: create the destination, break inheritance, assign the minimum groups, test with representative identities, then load. The day's evidence supports the decision to purge and redo the load. It does not confirm the completed reload, so I am not calling that final state shipped. #type/win

The day also produced several positive platform outcomes. I submitted a request to add the Microsoft Work IQ connector suite to the default Copilot Studio policy, with a documented rationale covering chat, meetings, mail, calendar, documents, OneDrive, and SharePoint grounding. The platform owner agreed to include the broader suite.

I demonstrated that an image could be processed into structured text and written to a SharePoint list now that Dataverse and tool access were working. I identified audio and meeting transcripts as adjacent patterns, but those extensions were not yet implemented.

I also helped bring an executive chief-of-staff agent online and shared its purpose and instructions with pilot users. One user confirmed access worked. This was an enabled pilot, not a production-wide release.

For data-science packages, I recommended Azure Artifacts as an enterprise-accessible feed rather than manually curating exact source archives. The proposal acknowledged storage limits and the need for role management. It was a design recommendation, not an approved operating service.

## The reusable pattern

Make security preflight a hard gate before ingestion. Validate inheritance, groups, test identities, sensitive columns, export paths, and rollback before the first record is written.

## Standing takeaways

-

Hidden columns are not access control.

-

Permission design must precede bulk loading.

-

A deliberate purge is better than preserving a risky shortcut.

## Open thread

The dataset still needed a verified reload into a least-privilege destination.
