# The Daily: Scale Metadata With Evidence

The catalog had enough reports to make manual enrichment expensive, but not enough trustworthy metadata to make automated discovery reliable.

## The theme: Human review belongs inside the pipeline

I demonstrated an AI-assisted process for enriching metadata across an initial set of Power BI reports. The workflow exported catalog data, generated missing descriptions and related fields, and kept people in the review loop.

The demonstration surfaced the real scaling requirements. Security and prompt-injection risks needed review. Generated metadata needed routine sampling. Permissions and approvals had to be explicit before the process expanded beyond the initial scope.

This shifted the work from a useful script toward a governed enrichment pipeline.

## Field notes from the build

The strongest design decision was to keep the source catalog exportable and the generated changes reviewable. That made it possible to compare old and proposed metadata before publication.

The meeting produced concrete follow-up work: conduct a security and governance review, develop a quality-control sampling strategy, coordinate required permissions, and delay broader demonstrations until those concerns were addressed.

I also contributed to an AI community discussion about acceptable tool use and approval paths. The transcribed meeting connected organizational use of AI tools to established review and steering processes. I shared that organizational tools need identification and approval before adoption. This was a governance clarification, not a new policy created by me.

A separate transcribed session covered renewal of Azure DevOps access tokens and secure storage. The session showed that token renewal was recurring operational work and that access to the password-management system still needed clarification for several groups. I was assigned to request the access needed to help manage keys and folders.

Automated pipeline notifications again showed executions that completed with mismatched counts or warnings. They supported the same lesson as metadata sampling: automation needs a second layer that evaluates output quality. #type/learning

## What moved

-

Demonstrated AI-assisted metadata enrichment for a bounded Power BI catalog scope.

-

Identified security, prompt-injection, quality-sampling, permission, and approval requirements before scaling.

-

Advanced a human-in-the-loop review model for generated metadata.

-

Clarified organizational AI approval expectations in a transcribed community session.

-

Learned and documented the recurring token-renewal workflow and its access dependencies.

## The reusable pattern

Treat generated metadata as a proposed change set. Preserve the source, capture the prompt and model configuration, score completeness, sample outputs, route defects, and require approval before publication.

The future state is a scheduled enrichment pipeline with deterministic schemas, risk checks, drift monitoring, and an exception queue for human review.

## Standing takeaways

-

Metadata generation is easy. Metadata trust is the product.

-

Sampling and defect capture must exist before scale.

-

Credentials and permissions are part of the operating model.

## Open thread

The enrichment workflow still needed an approved security review and measurable acceptance thresholds.
