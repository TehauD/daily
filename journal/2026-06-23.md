# The Daily: Test the Behavior, Not the Pitch

A useful AI demo should make its constraints visible. Today I put a contract-focused assistant in front of a working group and used the session to test behavior, not just presentation.

The agent could accept a document, compare terms against a reference standard, flag deviations, and vary the output depth. The important result was not that it produced a polished answer. It was that real users exposed where readability, access, licensing, and follow-up behavior still needed work.

## The theme: Evaluation begins when another person drives

Before the session, I prepared a simple flow: review the instructions, let a tester use the test environment, and gather feedback. I had also implemented small, medium, and large output modes so the same evaluation logic could support triage, action, or deeper analysis without changing the underlying conclusions.

The transcribed working session demonstrated document upload, comparison against a reference, risk flagging, confidence information, and configurable output. The discussion identified strengths in risk identification and summarization while surfacing improvement areas around readability and licensing.

A Teams installation attempt was blocked. That was useful evidence. Distribution is part of the product, and an agent that works only inside the authoring experience is not ready for broad use.

## Field notes from the build

The output-mode design separated presentation from evaluation. The small mode reduced columns for quick triage. The medium mode added severity and indicators for action. The large mode added alignment, impact, confidence, location, and evidence fields for deeper review.

The core rule was deliberately strict: changing the presentation must not change the evaluation result. That creates a testable contract across modes and reduces the risk that a concise view quietly hides a different conclusion.

The day also included a transcribed reporting architecture discussion. A dashboard currently read from SharePoint, and the team needed to decide between direct query and a fuller ETL path into Synapse. I was assigned to help determine that path. The meeting supported the need for broader access and additional reporting, but did not establish a final architecture decision.

In a separate remediation session, I compared security-model data across systems, identified a duplicate candidate, and recommended pausing removal until another validation pass before go-live. That choice reflected the same principle as the agent test: observation should precede irreversible change.

## What moved

-Demonstrated a contract-focused Copilot Studio agent in a transcribed working session.

-Implemented and tested three presentation modes over a consistent evaluation model.

-Gathered user feedback on risk findings, summaries, confidence, readability, and licensing.

-Identified a Teams distribution blocker during real use.

-Advanced the architecture decision between direct SharePoint reporting and a Synapse ETL path.

-Compared security-model records and deferred deletion pending validation.

## The reusable pattern

Define evaluation invariants before designing presentation variants. Store one structured result, then render it for different operating needs.

Run every agent through a user-driven test that covers access, document ingestion, reference grounding, follow-up questions, failure behavior, and export. Record each finding as evidence, not anecdote.

## Standing takeaways

-A demo becomes an evaluation when another person controls the workflow.

-Distribution and licensing are product requirements.

-Concise output should not change the underlying judgment.

## Open thread

The next test needs to verify Teams access and confirm that output modes remain logically equivalent across a larger contract set.
