Questions, answered

Everything you're wondering

Is my data really private?
Yes. The Daily runs entirely in your browser from one HTML file. Nothing is transmitted unless you explicitly push to a repository or invoke AI. Tokens and keys stay in your browser's local storage — never on a server we control, because there is no server.
Do I need Obsidian to use it?
No. The Daily is a complete journal on its own, with its own Browse graph, timeline, and search. Because it exports Obsidian-native frontmatter, tags, and wikilinks, your entries drop into a vault whenever you want — no conversion, no lock-in.
How does the AI work — and is it required?
It's completely optional and review-first. AI drafts into a workspace for you to accept or discard; it never rewrites your journal automatically. Bring your own provider — OpenAI, Azure OpenAI, Foundry, or a local model via LM Studio/Ollama/relay.
What does “automatic tagging” actually do?
As you write, The Daily detects decisions, learnings, blockers, experiments, ideas, and wins, and stamps the matching #type/* tag inline, aggregating them into frontmatter for the graph. It's idempotent — running it twice never creates duplicates.
How do I back up or move my journal?
Export the whole journal to a single JSON file, or push per-day Markdown to GitHub/Azure DevOps. Restore on any device by importing the backup or pulling from your repo. You always hold portable, standard formats.
What does it cost to run?
Nothing. The app is one HTML file you open locally, so there is no hosting bill. Storage is your own Git repository — GitHub gives unlimited private repos on the free tier, and Azure Repos is included with Azure DevOps. Years of daily Markdown amount to a few megabytes. The only optional cost is AI, and only if you point it at a paid provider instead of a local model.
What's the install process?

Three steps, about a minute:

  1. 1
    Clone the repo
    git clone https://github.com/TehauD/daily.git && cd daily
  2. 2
    Set your variables
    cp .env.example .env
    Add your GitHub or Azure Repos token and, if you want AI, your model endpoint and key. The .env file is git-ignored — credentials stay on your machine.
  3. 3
    Run it
    python relay.py
    Open http://127.0.0.1:8000 and start writing.

Running locally is the recommended setup: your tokens never touch a hosted origin. You can also just open index.html straight from the clone — everything except the relay-backed features works offline, with no Python at all.
